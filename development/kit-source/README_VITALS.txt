MiusVitals v7.1.1 — доставка Vitals и guard `basic_render`
===================================================

ВАЖНО: пакет проверен статически, структурой PE/ZIP и нативными тестами ASan/UBSan.
Запустить два настоящих экземпляра Graviteam Tactics в среде сборки нельзя. Сделайте
резервную копию папки игры и проверьте первый бой с двумя игроками. ОБА игрока должны
установить один и тот же MiusVitals v7.1.1.

Быстрая установка
-----------------
1. Установите оригинальный MiusPlayer v20 и закройте игру.
2. Распакуйте этот архив в папку игры. Должен получиться путь:
   ...\Graviteam Tactics Mius-Front\MiusVitals\Install_Vitals.bat
   Рядом с папкой MiusVitals должны быть starter_x64.exe и mpmod1.
3. Сначала запустите Check_Build.bat. Он ничего не меняет и пишет build_report.txt.
   Для поддерживаемых файлов в нём должно быть "same".
4. Запустите Install_Vitals.bat. Он сохранит исходный basic_network.codelib в
   MiusVitals\state и установит mp_vitals.dll в корень игры.
5. Так же установите ЭТОТ ЖЕ v7.1.1 второму игроку.

Откат: полностью закройте игру и запустите Uninstall_Vitals.bat. Исходный сетевой
модуль будет возвращён из MiusVitals\state либо из mpmod1. Не удаляйте state до отката.

Что исправляет v7.1.1
----------------------
Vitals — это необратимые состояния пехоты (смерть/ранение) и осторожно объединяемые
флаги техники. В v7.1.0 прежняя fire-and-forget посылка получила наблюдаемый транспорт;
v7.1.1 сохраняет его без изменения протокола:

* данные — сетевой type 52 (0x34), ACK — type 53 (0x35); это НЕ старый Vitals type 50
  (0x32), поэтому расширенный заголовок не будет ошибочно понят старой DLL;
* каждый data-пакет имеет ненулевые epoch и sequence;
* получатель сначала успешно кладёт весь пакет в mailbox, затем подтверждает его;
* отправитель удерживает до 32 неподтверждённых пакетов, отправляет те же байты снова
  через 400 мс и прекращает после 12 повторов;
* дубликат не применяется второй раз, но снова получает ACK; если mailbox заполнен,
  ACK намеренно не посылается — отправитель повторит пакет;
* каждые 5 секунд basic_network_*.log содержит строку:
  "vitals: state channel v7.1: packets sent ..., acked ..., retried ..., replaced ..."
  В нормальной связи sent и acked должны расти близко друг к другу, pending обычно 0.
  Небольшие retried допустимы. Постоянные pending/retried/replaced или inbox full —
  причина сохранить логи обеих сторон.

Что намеренно НЕ меняется
--------------------------
Native MiusPlayer type 10 (упорядоченные игровые записи: выстрелы и т. п.) и type 11
(его подтверждения) не исправляются и не переписываются. DLL только считает их в
диагностике и передаёт исходному MiusPlayer как есть. В присланном логе type-11 ACK
приходят штатно; доказательства поломки этого механизма нет.

Защита `basic_render` в v7.1.1
--------------------------------
Новый GT3 minidump гостя подтверждает второй точный read-AV в Steam 3598:
`basic_render.codelib+0x12ffd`, инструкция `mov ecx,[rdi+0x38]`. Рекурсивный walker
получил повреждённый номер child node (`R8 = 0x3f800000`) и построил недопустимый RDI.

Для точного timestamp и четырёх проверенных машинных сигнатур DLL теперь бережно
пропускает этот один child и переходит на штатный epilogue walker. Уже защищённый путь
`basic_render+0x13adb` остаётся отдельной ветвью. Корректный child index (<= 0x3ff),
иной RIP, write-AV либо иной адрес доступа не перехватываются. В логе после успешной
инициализации должна быть строка:

  vitals: basic_render invalid-child crash guards armed (rvas 12ffd, 13adb)

Оставлены прежние защитные меры:
* неподвижные юниты отправляются на каждом тике по умолчанию. MP_IDLE_MS=500 задаёт
  повтор раз в 0,5 секунды; MP_IDLE_MS=2000 близок к исходному MiusPlayer;
* MP_RENDER_GUARD=0 отключает ОБЕ узкие ветви basic_render только для диагностики.

Переменные среды
----------------
MP_VITALS=0        выключить Vitals; 1 — только сравнение/лог; 2 или 3 — применять.
MP_VEHICLES=0/1/2  выключить / только лог / применять синхронизацию статусов техники.
MP_STATS=0         не задавать одинаковый seed статистики после боя.
MP_LOG_VITALS=1    журналировать отдельные Vitals-события.
MP_IDLE_MS=N       интервал повторной отправки неподвижных юнитов в миллисекундах.
MP_RENDER_GUARD=0  выключить только строгий guard basic_render.

Глобальная карта операции
--------------------------
Само подключение в лобби не означает, что второй opgame участвует в общем ходе карты.
Для запроса подтверждения следующего хода MiusPlayer ждёт от второго opgame handshake
map-mode с тем же epoch. Пока его нет, хост по дизайну не ждёт подтверждения клиента.

Если у клиента карта открыта, но он не может отдавать приказы, либо хост может пропустить
ход без ожидания клиента, не заменяйте codelib вручную. После воспроизведения сохраните:

* полный basic_network_*.log хоста и клиента, начиная до перехода из боя на карту;
* command line и строки "net:" / "map:" / "unknown game build" из обоих логов;
* build_report.txt и указание, кто хостил, кто подключался, в какой момент пропал ход.

Присланный короткий opgame-лог завершился до handshake и не доказывает точную причину;
поэтому v7.1.1 не содержит непроверенного патча хода операции.

Проверка файлов
---------------
Этот комплект подходит только для Steam game build 3598 + MiusPlayer v20. Контрольные
суммы игровых файлов находятся в known_3598.sha256. Основные файлы комплекта:

  files/mp_vitals.dll                     SHA-256 3B74FF7F1B8D9F32488AE3678BD57CFE9F98A2574C1A2ACF207DC9111ADB3988
  files/basic_network.codelib             SHA-256 7CAF36CDDABF7EB388A3C6C393B05733E051955D63D32EF13531CE88004DCFBA
  files/alt/basic_network_nostart.codelib SHA-256 2FB049B9B465DE2E05BD9BBE7D5573A772319CC4D65FB20BB146E648A7CDF8EC
  files/alt/basic_network_v5_norebase.codelib SHA-256 D2E34581B42D0573547E221873D7538B64A413267E8ED388ABEB46DD42B630D2

Если Install_Vitals.bat сообщит, что модуль неизвестен, ничего не было изменено. Не
обходите эту проверку: пришлите build_report.txt. Варианты Install_Vitals.bat nostart
и Install_Vitals.bat norebase предназначены только для отката/диагностики совместимости.

Содержимое архива
-----------------
В ZIP ровно 16 файлов под единственным корнем MiusVitals/: установщики, hashes, эта
инструкция, исходники и тест, DLL и три варианта basic_network.codelib. В нём намеренно
нет репозиторных manifest/verifier/workflow/cache-файлов.
