# Папки версий

Каждая папка — полный исходник, из которого собран установщик с этим номером: `src`, `tests`,
`tools`, `fixtures`, `build.bat`, `run_tests.bat` и проекты Visual Studio 2026. Этого достаточно,
чтобы открыть папку в VS 2026 и отлаживать ровно то, что стоит у игроков.

| папка | что это |
| --- | --- |
| `1.0.7/` | бэкап: исходник установщика 1.0.7, больше не меняется |
| `1.0.8/` | рабочая: правки для 1.0.8 вносятся здесь |

## Как работаем каждой версией

1. Новая версия — копия предыдущей папки. Правки вносятся в копию, прошлая папка остаётся бэкапом.
2. Из исправленной папки собирается установщик.
3. Вышла следующая версия — позапрошлую папку удаляем. Создали 1.0.9 → удалили 1.0.7, 1.0.8 осталась
   бэкапом. Дольше двух версий в `development/` не живёт: самый старый архив — 1.0.0 в корне.

## Почему рядом лежит `development/net-v21/`

Это временное зеркало рабочей версии: все воркфлоу CI собраны по путям `development\net-v21\…`,
и до отдельного разговора про объём проверок мы их не трогаем. Перед сборкой релиза содержимое
папки версии копируется в `net-v21/`:

```sh
python3 scripts/sync_ci_tree.py 1.0.8    # development/versions/1.0.8 -> development/net-v21
```

Скрипт переносит файлы, удаляет исчезнувшие и проверяет, что после копирования обе папки
побайтово совпадают. Когда CI переедет на папки версий, зеркало удаляем.
