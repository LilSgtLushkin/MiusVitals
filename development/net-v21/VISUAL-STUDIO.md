# Сборка в Visual Studio 2026

Проект для IDE лежит рядом с `build.bat`: открываете решение — и собираете. Флаги в проектах
повторяют `build.bat` один в один, выходы попадают в те же папки.

## Что нужно на машине

* **Visual Studio 2026** с компонентом «Разработка классических приложений на C++». Её тулсет —
  **v145** (`cl.exe` 14.50 и выше), именно он указан в проектах.
* Windows 11 SDK (ставится вместе с этим компонентом; Windows 10 SDK в VS 2026 больше нет, и он
  нам не нужен).

Файл решения — `net-v21.slnx`. Это родной формат Visual Studio 2026 (XML вместо старого `.sln`).
Его же открывает VS 2022 начиная с 17.14; если понадобится старый `.sln` — скажите, добавлю.

## Как открыть

`development\net-v21\net-v21.slnx` — двойной щелчок либо «Файл → Открыть → Проект или решение».
Конфигурации: **Debug | x64** и **Release | x64**, других нет (игра 64-битная).

## Что внутри

| Проект | Что собирает | Куда | Зачем |
|---|---|---|---|
| `net-v21-module` | `basic_network.codelib` — наш модуль | `build\module\` / `build\module-debug\` | то, что подкладывается в игру |
| `net-v21-baseline` | `basic_network.codelib` из исходников v12 | `build\baseline\` / `build\baseline-debug\` | эталон для сравнения: те же исходники без наших правок |
| `net-v21-join` | `mp_join.exe` | `build\join\` / `build\join-debug\` | подключение к серверу из командной строки |
| `net-v21-object-check` | `transform_object_check_test.exe` | `build\selftest[-debug]\` | построчный прогон проверки объекта перед записью трансформа |
| `net-v21-render-test` | `render_guard_test.exe` | `build\render_test[-debug]\` | быстрая проверка защиты рендерера |
| `net-v21-selftests` | все 44 теста | `build\selftest[-debug]\` | Makefile-проект: вызывает `build.bat selftest` и `run_tests.bat` |

Общие флаги вынесены в `net-v21-common.props`: `/W3`, C++14, без PCH, без `/sdl` и `/permissive-`,
без `/Gy`, `/Oi`, `/GF` — то есть ровно то, что получается при сборке голым `cl.exe`.

## Чем отличаются конфигурации

| | Release | Debug |
|---|---|---|
| Оптимизация | `/O1` | `/Od` |
| Символы | нет | `/Zi`, на линковке `/DEBUG` |
| Определения | — | `NETV21_DEBUG` |
| Воспроизводимость | `/Brepro` компилятору и линковщику | — |
| Runtime | `/MD` | `/MD` (не `/MDd`: модуль грузится в процесс игры) |
| Исключения | `/EHa` у модуля и baseline, `/EHsc` у тестов | так же |

`net-v21-join` — единственное исключение: `build.bat` собирает его всегда с `/MT /O1 /Brepro`,
даже в Debug. Проект это повторяет; отладочные символы в Debug у него есть.

Пути выходов совпадают с `build.bat`, поэтому результаты можно сравнивать. Промежуточные объектные
файлы проекта складываются отдельно — в `build\msbuild\<проект>\x64\<конфигурация>\`, чтобы не
смешиваться с объектами `build.bat` (и не мешать ему).

## Переменные окружения

* **`MIUS_GAME_DIR`** — путь к папке игры. Если она задана:
  * после сборки `net-v21-module` готовый `basic_network.codelib` и его `.pdb` копируются в папку
    игры (post-build шаг);
  * **F5** в конфигурации Debug запускает игру (`tacgame.exe`) из этой папки.
  Переменную удобно задать один раз: `setx MIUS_GAME_DIR "D:\Games\Mius"`.
* **`MIUS_VS`** — принудительно указать установку Visual Studio для `build.bat`
  (например `C:\Program Files\Microsoft Visual Studio\18\Community`). Нужен только если студий
  несколько или она стоит в нестандартном месте.

## Отладка

1. Соберите `net-v21-module` в Debug.
2. Подложите модуль в игру: либо задайте `MIUS_GAME_DIR` (тогда шаг 2 делает сам post-build), либо
   скопируйте `build\module-debug\basic_network.codelib` и `basic_network.pdb` в папку игры вручную.
3. Запустите игру и нажмите **Отладка → Присоединиться к процессу → tacgame.exe** (или
   `opgame.exe`). Либо просто **F5**, если задан `MIUS_GAME_DIR`: студия запустит игру сама.
4. Точка останова в `src\session.cpp` сработает — символы берутся из `build\module-debug`.

Проверить, что модуль загрузился, можно по логу: в папке игры появляется `netlog` с записью версии.

## Про отношение к build.bat

CI и установщик собираются через `build.bat` — он остаётся главным. Проекты нужны для работы в IDE
и повторяют его флаги; если они когда-нибудь разойдутся, ориентиром считается `build.bat`.
`net-v21-selftests` вообще не компилирует ничего сам, а вызывает `build.bat` и `run_tests.bat`,
поэтому список тестов в нём всегда совпадает с CI.
