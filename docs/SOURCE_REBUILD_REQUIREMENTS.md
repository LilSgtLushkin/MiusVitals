# Что нужно для корректной работы над модом (после решения 2026-10-26)

Документ отвечает на вопрос «что требуется, чтобы исправлять дефекты G1–G7 в корне, а не
случайным патчем байтов». Он фиксирует фактическое состояние релизного модуля, что у нас
есть, чего не хватает и при каких условиях правка не ухудшит работоспособность мода.

> **Решение 2026-10-26 (принято, не обсуждается).**
> * Исходника v20 нет и получить его невозможно. Запрос к автору снят.
> * **Совместимость с v20 не требуется** — мы делаем свой мод, а не продолжаем чужой.
>   Байтовое совпадение с `8108bd1e…` больше не цель и не критерий.
> * Выбран **путь B**: правим то, что у нас есть, — релизный `basic_network.codelib`
>   (v20 + наши патчи) и `mp_vitals.dll`, — а новую логику пишем в C++ в своём модуле.
> * **Одобрен перенос логики Vitals в C++**: медленно, по этапам, с тестами на каждом шаге
>   и точкой отката перед каждым этапом. План — [`VITALS_CPP_PORT_PLAN.md`](VITALS_CPP_PORT_PLAN.md).
> * Следствие: документ больше не «заявка автору», а **реестр ограничений нашего
>   собственного процесса**.

## 1. Что представляет собой релизный модуль

| Параметр | Значение |
|---|---|
| Варианты | main `377 856` Б (`485b6556…02a3`); FPS-релиз `378 368` Б (`7b42a69a…1f67`) |
| PE timestamp | `0x6ACFAA3D` — тот же, что у v20 (`2026-10-14 16:13:49 UTC`) |
| Секции | `.text` `0x1000` (`0x42e68`), `.rdata` `0x44000`, `.data` `0x5a000`, `.pdata` `0x5f000` (895 функций), `.reloc` `0x62000`, `.mpimp` `0x63000`, `.fpsfix` `0x64000` (только релиз) |
| Импорт | `USER32`, `GDI32`, `WS2_32`, `ole32`, `OLEAUT32`, `MSVCP140`, `VCRUNTIME140`, `VCRUNTIME140_1`, `api-ms-win-crt-*`, **`mp_vitals.dll!MpVitalsInit`** |

`f8c89ed0…`, побайтово совпадающий с `485b6556…` во всех секциях, кроме добавленной `.mpimp`.

### Steam-слой: что резолвит модуль и что подтверждено по вашей DLL

Интерфейсы: `SteamAPI_SteamFriends_v017`, `SteamAPI_SteamUser_v021`,
`SteamAPI_SteamNetworking_v006`, `SteamAPI_SteamUtils_v010`.

Функции (21 имя): `ISteamUser_GetSteamID`, `BLoggedOn`, `ISteamUtils_GetAppID`,
`ISteamFriends_GetPersonaName`, `SetRichPresence`, `GetFriendRichPresence`,
`RequestFriendRichPresence`, `GetFriendCount`, `GetFriendByIndex`, `GetFriendPersonaName`,
`GetFriendGamePlayed`, `ISteamNetworking_SendP2PPacket`, `IsP2PPacketAvailable`,
`ReadP2PPacket`, `AcceptP2PSessionWithUser`, `AllowP2PPacketRelay`,
`SteamAPI_RegisterCallback`.

Rich presence: ключ `+gtmf_join=steam:<id>`; отключение — `MP_STEAM=0`; тестовый
стенд — `MP_STEAM_FAKE=<id>` (локальная UDP-эмуляция Steam на одном ПК).

**Сверка ABI выполнена 2026-10-26 по присланной `steam_api64.dll`** (298 384 Б,
sha256 `1db3fd41…a1af3`):

| Проверка | Результат |
|---|---|
| Версия файла | `07.40.51.27`, Steam Client API, Steam 2022-07-29 (`ts 0x62E325B2`) — ровно эпоха этой игры |
| Экспортов всего | 2 132 (export RVA `0x33760`, size 57 744) |
| `SteamFriends017` / `SteamUser021` / `SteamUtils010` / `SteamNetworking006` | **все четыре есть** |
| Все 21 функция по именам | **все есть** |
| `steam_api64_o.dll` | побайтово идентична исходной (обе копии = оригинал) |

Вывод: ревизия интерфейсов совпадает с ожиданиями модуля; ABI-риска по Steam больше нет.
Проверка остаётся в реестре только потому, что игру можно обновить.

## 2. Границы: что мы можем менять и как

| Слой | Кто владеет исходником | Как менять | Риск |
|---|---|---|---|
| `basic_network.codelib` (v20 ядро, 293 функции без исходника) | никто | только байтовые патчи скриптами с проверкой хешей и NOP-безопасных окон | средний: правка в непроверенном месте — падение игры |
| `mp_vitals.dll` (наш C++) | **мы полностью** | обычная сборка, тесты, версии | низкий |
| Комплект поставки (bat/ps1/тексты/zip) | мы | свободно | нет |

Отсюда стратегическое правило: **всё новое поведение пишется в `mp_vitals.dll`**, в codelib
допускаются только точечные проверенные патчи. Именно поэтому одобрен порт Vitals в C++.

| # | Что | Зачем | Статус |
|---|---|---|---|
| 1 | Два ПК с игрой Steam 6.00 build 3598/1 и два Steam-аккаунта-друга | единственный способ проверить Steam-путь (у upstream он не проверялся ни разу) | **прогон 2026-10-26** |

## 5. Порядок работы (действующий процесс)

1. **Baseline.** Двух-ПК прогон v1.0.1 по
   [`TWO_PC_TEST_PLAN_2026-10-26.md`](TWO_PC_TEST_PLAN_2026-10-26.md); результаты —
   в [`docs`](README.md), хеши — в `BUILD_AND_VALIDATION.md`.
2. **Один дефект — один патч.** Мелкие правки codelib: скрипт + проверка хешей + строка в
   `NETWORK_LIMITATIONS.md`; при сдвиге кода — пересчёт RVA-профиля.
3. **Новая логика — только в `mp_vitals.dll`.** Этапы и откаты —
   [`VITALS_CPP_PORT_PLAN.md`](VITALS_CPP_PORT_PLAN.md).
4. **Перед каждым релизом** — `sh scripts/verify_release.sh` (ALL OK), затем двух-ПК
   приёмка, затем версия и архив.
5. **Откат** — предыдущая версия (`v1.0.1`) остаётся в git; каждый этап порта коммитится
   отдельно, чтобы откат был на один `git revert`.

## 6. Чего делать нельзя

* **Пересобирать из публичного v12 и выдавать это за v20.** Это откат: −293 функции,
  −Steam, −выбор отряда, −ceasefire, −hits/anim/craters и т.д.
* **Применять текущий `patch_import.py` к другому билду codelib.** Профиль RVA привязан к
  `485b6556…`; на другом билде DLL не должна загружаться.
* **Менять длину кода в `.text` без пересчёта профиля DLL.** Молчаливое «guard не включился»
  хуже, чем отказ загрузки.
* **Выпускать сборку с изменённым Steam-слоем без двух реальных аккаунтов.**

## 7. Риски

| Риск | Последствие | Смягчение |
|---|---|---|
| Патч в непроверенном месте v20-кода | падение игры у игроков | только NOP-безопасные окна, хеш-проверка, откат версией |
| Сдвиг RVA после патча | `mp_vitals` не загрузится или не включит guard | профиль RVA в репозитории + `verify_artifacts.py` |
| Steam-путь не проверен двумя аккаунтами | Steam-друзья могут не работать у игроков | прогон 2026-10-26; при отказе — адресный режим как основной |
| Порт Vitals в C++ ломает тайминги | лишние/пропущенные пакеты, фризы | поэтапный порт с A/B на одной сессии, точка отката на каждом шаге |
| Рассинхронизация документации и кода | ложные выводы при разборе | документ обновляется в том же коммите, что и код |
