Исходники `_mp_research/basic_network/` — полезное описание структур и логики, но release v20 содержит более новый код (Steam P2P, друзья, UPnP), поэтому адреса и байты release всегда сверяются отдельно.

## Нативный надёжный поток

В v20 type **10** несёт упорядоченные игровые записи; type **11** подтверждает активную session и непрерывно принятый sequence. Дизассемблирование release подтверждает этот путь в обработчике получения: type-10 передаётся в штатную упорядоченную обработку, а type-11 обслуживает её native ACK/retirement состояние.

Анализ host tactical log нашёл 20 485 входящих type-11 ACK за 233 пятисекундных интервала. Это доказывает активность ACK-механизма, но само по себе не доказывает ни безошибочность, ни дефект native очереди. Поэтому MiusVitals v7.1.0 **не меняет** type-10/type-11: их байты всегда отдаются оригинальному обработчику. Нативный тест специально утверждает этот pass-through.

## Почему изменён отдельный Vitals-поток

Старые Vitals-сообщения были custom type 50 (`0x32`) и уходили через Steam P2P как fire-and-forget. В том же tactical log получены 1 920 type-50 датаграмм в 279 интервалах, причём в 69 интервалах их не было. Этот счётчик не даёт наблюдаемого результата доставки конкретного состояния и не является подтверждением native type-10 поломки.

v7.1.0 строит отдельный прикладной транспорт только для Vitals:

- Vitals data: type 52 (`0x34`); ACK: type 53 (`0x35`);
- заголовок — native `Head` плюс ненулевые `epoch`, `seq` (16 байт всего);
- sender queue: до 32 точных пакетов; retry 400 мс; максимум 12 retries; ACK retire только по совпадающей паре `(epoch, seq)`;
- receiver: mailbox на 128 пакетов; ACK только после помещения; duplicate повторно ACK'ается без повторного применения; полный mailbox не ACK'ается;
- telemetry каждые пять секунд делает транспорт наблюдаемым.

Пакетная нумерация отделена от type 50, чтобы расширенный заголовок не интерпретировался старой DLL как список Vitals entries.

## Что меняет MiusVitals

MiusVitals не заменяет игровые модули и не меняет сохранения. `patch_import.py` добавляет ровно один PE import: `mp_vitals.dll!MpVitalsInit`. При загрузке DLL:

1. проверяет timestamp и сигнатуры точек перехвата;
2. перехватывает кадр и обработчик входящих пакетов базового модуля;
3. синхронизирует необратимые состояния пехоты и осторожные статусы техники через custom Vitals transport;
4. пропускает каждый native packet type, кроме зарезервированных 52/53, в исходный обработчик;
5. при точной сигнатуре меняет два immediate у отправителя позиций для периода неподвижных юнитов (`MP_IDLE_MS`);
6. содержит узкий guard конкретного сбоя `basic_render`, включаемый только после строгой проверки образа.

Если сигнатура не проходит, соответствующее изменение не включается. Это снижает риск на чужой сборке, но не заменяет тест двух реальных игроков.

## Steam

Строки из v20-бинарника подтверждают `SteamAPI_SteamNetworking_v006`, `SteamFriends_v017`, `SteamUser_v021` и `SteamUtils_v010`. Поэтому v20 уже использует Steam P2P; MiusVitals не добавляет сетевых API и не заменяет этот транспорт.

## Ограничения

- Комплект рассчитан только на MiusPlayer v20 и Steam build 3598/1, для которого подготовлен rebase.
- После 12 повторов Vitals packet снимается с ограниченной очереди, чтобы ушедший peer не расходовал память бесконечно. Telemetry должна использоваться для обнаружения такого случая.
- Нативные тесты подтверждают логику и формат патча, но не являются совместным прогоном в игре.
