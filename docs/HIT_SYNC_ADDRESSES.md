# Попадания в `adv_physic`: проверенные адреса и состояние работы

Снимок пользовательской папки `x64` от 27.10.2026 сохранён в репозитории:
[`development/game-build-3598-1/x64/`](../development/game-build-3598-1/x64/).
В нём есть `adv_physic.codelib`, поэтому файлы для анализа этой сборки уже есть и повторно их
запрашивать не нужно. Папка — справочный снимок, **не установщик**.

## 1. Что подтверждено по файлу

`adv_physic.codelib`: 931 328 байт, SHA-256
`c130dc38054a47b8cf1ddd9301835af552b45b96d252a528a9addd518ea3cf6e`, PE timestamp `0x66f2a91e`,
предпочитаемая база `0x180000000`.

Смещения в таблице — RVA относительно базы модуля. Ранее это были гипотезы из
`development/kit-source/src/rebase_3598_1.py`; теперь значения указателей в переданном файле
проверены непосредственно:

| назначение | слот RVA | 8 байт в файле (little-endian) | цель RVA |
|---|---:|---|---:|
| `i_techn` (техника) | `0xC79D8` | `30 32 04 80 01 00 00 00` | `0x43230` |
| `i_human` (люди) | `0xC6760` | `90 6C 06 80 01 00 00 00` | `0x66C90` |

Оба указателя находятся в `.rdata` и в файле содержат предпочитаемый VA
(`0x180043230` и `0x180066C90`); цели находятся в `.text`, а их границы описаны в `.pdata`.
Это подтверждает значение и расположение указателей в данном файле, но не доказывает ABI или
корректность обработки всех случаев попадания в живой игре.

## 2. Как воспроизвести проверку

Из корня репозитория:

```sh
python development/game-build-3598-1/manifest.py --verify
python development/net-v21/tools/pe_scan.py development/game-build-3598-1/x64/adv_physic.codelib --at 0xC79D8 0xC6760
python development/net-v21/tools/pe_scan_selftest.py
python development/net-v21/tools/hook_audit.py
python development/net-v21/tools/hook_audit_selftest.py
```

`hook_audit.py` — **только офлайн-проверка**, она не устанавливает хуки и не изменяет процесс игры.
Для каждого кандидата она сначала сравнивает сигнатуру по фиксированному RVA, а при несовпадении
требует единственное совпадение в исполняемых секциях; таблицу указателей проверяет аналогично в
`.rdata`. Тесты намеренно меняют копии байтов в памяти и проверяют отказ при неоднозначности.

`pe_scan.py` печатает SHA-256, PE timestamp, секцию, байты, возможный указатель в код, границы
функции и её пролог. В отличие от RVA, обычный 64-битный указатель в PE-файле включает
**предпочитаемую базу образа**; инструмент учитывает её. Найденное значение помечается как
`possible pointer`: само по себе совпадение с адресом кода ещё не доказывает назначение поля.
Поиск `--sig` учитывает только исполняемые секции, как и проверка хуков; он выводит отдельно RVA
модуля и смещение внутри секции.

Для адресов из отладчика поддерживаются `--va АДРЕС --base БАЗА`; без `--base` используется
предпочитаемая база из файла. База отладчика нужна для пересчёта самого адреса, но содержимое
указателя в файле всё равно пересчитывается по предпочитаемой базе PE. Адрес ниже указанной базы
отклоняется; для RVA используется `--at`.

## 3. Анимации: что подтверждено статически

`adv_game.codelib` из того же снимка имеет SHA-256
`8f53c9018e7fc30a7e08daa16be5952a6aaec115412fa48245c2ee13046d1975`. По адресу `i_animch`
`0x12F128` проверены 11 указателей и соответствующие прологи: слоты 4, 8, 10, 11, 12, 13, 14,
16, 20, 21 и 26. В ряде соответствующих методов видна адресация массива по указателю объекта
`+0x140` и индексу с шагом `0x140`; это наблюдение по машинному коду, а не гарантия времени жизни
объекта, потоковой безопасности, ABI или правильности сетевого применения. Полный список RVA и
проверяемых сигнатур находится в `tools/hook_audit.py`.

## 4. Что ещё не готово

Проверка файла не является готовой синхронизацией попаданий. В `net_v21` ещё нет обработчика
`hit: ... sent` / `... carried out here`, переноса события и доказанного воспроизведения попаданий
по частям и анимаций. Не следует считать их реализованными только на основании этой таблицы.

При дальнейшем переносе нужны проверка ABI и состава события, корректная идентификация частей и
объектов в обеих играх, надёжная доставка и защита от повторной обработки. Перехват должен
проверять загруженные байты и указатели: сначала известное смещение, затем при необходимости
поиск подходящего однозначного совпадения, без предположений на другой сборке. При несовпадении
перехват не ставится и причина записывается в лог; уже существующие боевые механизмы не должны
ломаться. Внутренние тесты не заменяют проверки поведения в реальном бою.


## 5. Дополнительный статический разбор v20 (2026-10-28)

В проверенном по SHA-256 бинарном образце v20 обёртки `0x3cea4` и `0x3d104`
передают общей функции `0x3c99c` оригинальный адрес и признак типа цели. Видимая
переадресация сохраняет шесть исходных аргументов: указатель цели, указатель записи,
32-битное значение, указатель и ещё два значения из стека. Первые 104 байта записи
копируются, а дополнительные указатели и номера преобразуются перед передачей. При
воспроизведении `0x3c650` дополнительно переводит номер поражённой части через
`0x2f4d0`, проверяет цель и восстанавливает дополнительные указатели и состояние RNG.
Это более точная подсказка, чем одни RVA, но значения аргументов, обработка всех частей,
время жизни объектов, потоки и побочные эффекты в игре не установлены. Поэтому эти
обёртки **не подключены** к 1.0.7; полной реализации попаданий и анимаций здесь нет.
