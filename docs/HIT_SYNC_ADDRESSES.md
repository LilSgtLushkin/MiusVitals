# Попадания (hit) в adv_physic: какие адреса нужны и как их передать

Дата: 2026-10-27. Относится к остатку M3 — синхронизации попаданий по частям (`hit: kind/part`) и
анимаций солдат, как это делал v20.

## 1. Что именно нужно

v20 подменяет в `adv_physic.codelib` не функции напрямую, а **два слота виртуальных таблиц**: слот
начинает указывать на свою функцию модуля, а прежний адрес запоминается и вызывается оттуда. Перед
подменой он сверяет, что слот действительно держит ожидаемую функцию (8 байт), иначе ничего не
трогает и пишет в лог `hit: unknown game build, each game works out every hit for itself`.

| что | модуль | v20 | сборка 3598/1 (rebase) |
|---|---|---|---|
| слот `i_techn` (техника) | `adv_physic` | `0xC7A18` | `0xC79D8` |
| функция попадания по технике | `adv_physic` | `0x43230` | `0x43230` (не двигалась) |
| слот `i_human` (люди) | `adv_physic` | `0xC67A0` | `0xC6760` |
| функция попадания по людям | `adv_physic` | `0x66CC0` | `0x66C90` |

Источник: `development/kit-source/src/rebase_3598_1.py` (строки `hit: …`) и
`development/v20-recovery/reports/decomp/03cedc_unnamed.c` (`v6 + 817688`, `v6 + 812960`,
`v6 + 421056`).

**Чего не хватает:** не адресов, а **файла**. Смещения выше — из пересчёта v20 на сборку 3598/1;
на вашей сборке они почти наверняка те же (Start из `adv_interf` совпал с этим пересчётом), но
поставить перехват «по бумажке» нельзя: нужны настоящие байты по этим адресам, чтобы модуль
проверил и либо встал, либо честно сказал «не та сборка».

## 2. Как передать адрес

### Проще всего — не искать его вовсе

Пришлите **один файл**: `bin\rel\x64\adv_physic.codelib` (≈1 МБ), можно вместе с остальным
`bin\rel\x64`, как договаривались. Из файла я вытащу все четыре числа сам и подтвержу их байтами.
Ничего открывать и ничего смотреть не нужно.

### Если хотите дать адрес

Годится любая из этих форм — по одной на строку, остальное я восстановлю из файла:

| форма | пример | откуда |
|---|---|---|
| RVA от базы модуля | `adv_physic 0x43230` | x64dbg показывает `Модуль:adv_physic.codelib+0x43230`; это и есть RVA |
| абсолютный адрес + база | `adv_physic 0x7FF8A1233230, база 0x7FF8A11F0000` | из отладчика, если видно только адрес |
| адрес из IDA/Ghidra | `0x180043230, база образа 0x180000000` | там адрес с базой; назовите базу, я вычту |
| имя функции в IDA/Ghidra | `sub_180043230` / переименованная вами | плюс база образа |

Достаточно **одного** адреса из пары «слот ↔ функция»: слот ведёт к своей функции (по указателю в
нём), а функцию я найду по указателю на неё в `.rdata`. Адрес внутри функции тоже годится — начало
и границы берутся из `.pdata`.

**Обязательно вместе с адресом** — сам файл (или его `sha256`, размер и PE-штамп): без файла
адрес нечем проверить, а между сборками игры смещения сдвигаются (в прошлый раз Start уехал на
`0x90`, сохранение операции на `0x5e0`).

### Как это выглядит в сообщении

```
adv_physic.codelib  (1 043 456 Б, sha256 0123abcd…)
слот i_techn   0xC79D8 -> функция 0x43230
слот i_human   0xC6760 -> функция 0x66C90
сборка: как у вас (bin\rel\x64 от 26.10.2026)
```

Если снимали в x64dbg — можно просто скопировать строку из статусной строки CPU-вкладки
(`Module:adv_physic.codelib+0x43230`) и приложить `Get-FileHash adv_physic.codelib`.

## 3. Чем это проверяется с моей стороны

```sh
python development/net-v21/tools/pe_scan.py adv_physic.codelib --at 0xC79D8
python development/net-v21/tools/pe_scan.py adv_physic.codelib --va 0x7FF8A1233230
```

`--at`/`--va` печатают паспорт файла (размер, `sha256`, PE-штамп, база образа), секцию и смещение
внутри неё, границы функции из `.pdata`, её первые 32 байта (это и есть подпись для проверки) и,
если задан слот, — функцию, которую он держит, тоже с прологом. Обе команды работают на присланном
`basic_network.codelib`; пример:

```
basic_network.codelib --at 0x580a0
  rva      0x580a0   (.rdata+0x140a0)
  function no .pdata record here (data, or a leaf function)
  bytes    78 33 04 00 00 00 00 00 ...
  points to +0x43378  (.text+0x42378)  - the function this slot holds:
            function +0x43378..+0x433a4 (44 bytes)
            prologue 40 55 48 83 EC 20 48 8B EA 80 7D 20 00 75 16 4C 8B 4D 70 4C 8B 45 28 48 8B 55 58 48 8B 4D 50 E8
```

## 4. Что будет сделано с адресом

1. В `session.cpp` появится `hook_resolve` для двух слотов: сначала известное смещение этой
   сборки, затем поиск указателя на функцию по `.rdata` — как у остальных перехватов
   (`docs/HOOKS_AND_GAME_BUILDS.md`, §3).
2. Слот подменяется только после сверки: он должен держать ожидаемую функцию, иначе перехват не
   ставится и в логе остаётся `hit: unknown game build …` — бой при этом идёт как сейчас.
3. Появится `hit: %s struck (kind %u, part %x, ammunition %u), sent` / `… carried out here` — то,
   чего сейчас нет: попадания по частям (башня, ходовая, экипаж) и анимации будут одинаковыми в
   обеих играх.
4. Проверка — те же внутренние тесты плюс строка `hit: …` в `out\net_v21_tacgame.log` при первом
   попадании в живом бою; без адреса этот шаг не делается, чтобы не гадать.
