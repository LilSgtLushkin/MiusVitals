# Предупреждения VS 2026 (п.15)

## Правило

Предупреждения не глушатся массово и не снимаются настройкой проекта: каждое либо **настоящий
дефект** (тип не туда — правится код), либо **документированное сужение на границе протокола**
(оставляется явным приведением с комментарием, почему так можно).

## Что уже понятно без журнала сборки

`C4244` (сужение) в session.cpp стоит там, где 64-битное значение боевого времени или размера
кладётся в 32-битное поле пакета:

| Место | Что | Решение |
|---|---|---|
| `sh->sim_ms = (u32)g_sim_ms;` | поле пакета 32-битное по протоколу | приведение оставить, оно и есть граница |
| `e.sim_ms = (unsigned)g_sim_ms;` | то же | то же |
| `hello->force_size = (u32)g_force_out.size();` | размер описания в поле пакета | то же, но проверить, что размер не может превысить 4 ГиБ — по построению не может |
| `g_clock_factor = (float)scale;` | double в float, множитель часов | приведение осознанное: точность множителя не критична |
| `u32 kind = (u32)(kv.first >> 32);` | старшая половина ключа | осознанно, ключ собирается обратно |

Эти места уже имеют явные приведения — то есть предупреждение снято не подавлением, а показанным
намерением.

## Чего не хватает

Полного журнала сборки VS 2026: нумерация строк в `session.cpp` сместилась после правок, и
перебирать предупреждения по памяти — значит рисковать пропустить настоящее. Как только журнал
будет, каждое предупреждение разбирается по правилу выше: дефект правится, граница протокола
остаётся с комментарием.
