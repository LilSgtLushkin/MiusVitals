# MiusPlayer на GitHub: что там лежит и что такое v20

Дата разбора: **2026-10-26**. Источник: `github.com/VampyrCat/MiusPlayer`,
единственная ветка `main`, commit `43b2736d3b4a1e208e6c80f45f6ebbdd476de3aa`
(2026-10-14). Лицензия upstream — **CC0-1.0**.

Этот документ отвечает на вопрос «есть ли на GitHub исходник v20, на котором собран наш
мод». Короткий ответ: **исходника v20 там нет; v20 существует только как готовый
бинарник в `GTMPRelease1.zip`.** Публичный C++ — это предыдущая версия, **v12**.

> **Решение 2026-10-26.** Источник v20 закрыт как недоступный, совместимость с v20 не
> требуется. Разбор ниже сохранён как фактология (что именно находится в v20 сверх v12);
> действующий процесс — [`SOURCE_REBUILD_REQUIREMENTS.md`](SOURCE_REBUILD_REQUIREMENTS.md),
> порядок переноса Vitals — [`VITALS_CPP_PORT_PLAN.md`](VITALS_CPP_PORT_PLAN.md).

## 1. Короткий ответ

| Утверждение | Проверено |
|---|---|
| v20 — это не ветка, не тег и не GitHub Release, а архив `GTMPRelease1.zip` в корне репозитория | веток 1 (`main`), тегов 0, релизов 0 |
| Внутри архива — готовый `mpmod1` с `basic_network.codelib` «network version 20, built 2026-10-14 19:13» | README архива, PE timestamp |
| C++ исходники в репозитории — это **v12** (`k_version = 12`), они собирают модуль `eff7ae12…`, а не v20 | `protocol.h`, `build/basic_network.codelib` |
| Исходников v20 нет ни в одном коммите, ветке, zip, `.obj`, Ghidra-проекте или другом публичном репозитории | история из 6 коммитов; GitHub code search по `MP_STEAM_FAKE` и `gtmf_fake_steam` — 0 |
| Наш модуль собран именно из v20 | `rebase_3598_1.py` требует SHA-256 `8108bd1e…`; результат rebase совпадает с нашим модулем во всех секциях, кроме добавленной `.mpimp` |

Главное следствие: **пересборка из публичного исходника — это не «v20 без Steam», а
откат на v12**. Разница между v12 и v20 — 293 функции и ~107 КБ машинного кода, а не
только Steam-слой.

## 5. Steam-слой v20

**Загрузка.** `steam_api64.dll` не импортируется. Модуль вызывает
`GetModuleHandleA("steam_api64.dll")` и `GetProcAddress` по плоским именам; своей
`LoadLibrary` у него нет (в импорте KERNEL32 только `GetModuleHandleA/ExA` и
`GetProcAddress`). Если игра не загрузила Steam — в лог идёт
`steam: the game has not loaded Steam's library - no Steam joining`.

**Интерфейсы и функции** (17): `SteamFriends_v017`, `SteamUser_v021`,
`SteamNetworking_v006`, `SteamUtils_v010`; `GetSteamID`, `BLoggedOn`, `GetAppID`,
`GetPersonaName`, `SetRichPresence`, `GetFriendRichPresence`,
`RequestFriendRichPresence`, `GetFriendCount`, `GetFriendByIndex`,
`GetFriendPersonaName`, `GetFriendGamePlayed`, `SendP2PPacket`,
`IsP2PPacketAvailable`, `ReadP2PPacket`, `AcceptP2PSessionWithUser`,
`AllowP2PPacketRelay`, `RegisterCallback`.

**Callback-классы** (RTTI в `.rdata`): `JoinRequested`, `SessionRequest`,
`SessionFail`, `PresenceUpdate`.

**Размер.** Ядро слоя — 20 функций в конце `.text`, `0x3E7A4…0x3FD16`, ровно
**5 454 Б**. С учётом интеграции (диспетчер сессии, кадр сессии, экран JOIN A GAME,
список друзей) на Steam-строки ссылаются 20 функций общим размером **24 325 Б**.

**Rich presence.** Ключ `+gtmf_join=steam:<id>`; Steam запускает игру строкой
`root\programs\opgame.progpack, +gtmf_join=steam:<id>`; модуль разбирает
`GetCommandLineA()`. Отключение — `MP_STEAM=0`.

**Тестовый стенд.** `MP_STEAM_FAKE=<id>` поднимает локальную UDP-эмуляцию Steam:
игра считает себя `steam:<id>`, datagrams идут по loopback, а список «друзей»
читается из `%TEMP%\gtmf_fake_steam_<id>.txt`. Это позволяет **на одном ПК**
прогнать весь Steam-путь (presence, friend join, P2P) без двух аккаунтов. Автор пишет,
что стенд тест проходит; против настоящего Steam проверены библиотека, callbacks и
rich presence, но **два реальных аккаунта не проверялись**.

## 6. Наш модуль — это v20 плюс точечные патчи

Доказательство воспроизводимости (все шаги выполнены на этом разборе):

1. `python3 development/kit-source/src/rebase_3598_1.py GTMPRelease1.zip-модуль out.codelib`
   принимает только `8108bd1e…` и даёт `f8c89ed0…`.
2. Побайтовое сравнение `f8c89ed0…` с `development/kit-source/files/basic_network.codelib`
   (`485b6556…`): **`.text`, `.rdata`, `.data`, `.pdata`, `.reloc` идентичны**; отличие
   ровно одно — добавленная секция `.mpimp` (импорт `mp_vitals.dll!MpVitalsInit`).
3. Релизный `MiusMultiplayer_v1.0.1_INSTALL.zip` несёт `7b42a69a…` = `485b6556…` +
   секция `.fpsfix` (9 байт в `0x2C36` заменены на `jmp` + trampoline).

Итого от v20 до релиза:

| Изменение | Байт |
|---|---|
| 23 константы rebase под 3598/1 (`rebase_3598_1.py`) | 23 × 4 |
| NOP гонки Next Turn при hand-off карты (`0x15A77`) | 8 |
| Потолок state-потока 600 → 1500 КБ/с (`0x320A6`) | 4 |
| Две сигнатуры в `.rdata` (`0x48DA0`, `0x497A8`) | 18 |
| Секция `.mpimp` (импорт Vitals) | 512 |
| Секция `.fpsfix` (только в релизе) | 512 |

Остальные runtime-файлы нашего архива — **байт-в-байт из v20**: `mp_join.exe`
`6aa417cf…`, `opgame.progpack` `eca75b74…`, `tacgame.progpack` `01923eab…`,
`steam_appid.txt` `1a43840c…` (312980). То есть **вся функциональность v20, включая
Steam, присутствует в нашем моде**; в нашем README она просто не расписана.

## 7. Что это значит для пересборки исходника

| Путь | Что даёт | Оценка |
|---|---|---|
| **A. Получить исходник v20 у автора** | полная пересборка, любые фиксы в исходнике | единственный путь к настоящему source rebuild |
| **B. Продолжать точечные бинарные патчи** | текущий воспроизводимый процесс; v20 остаётся базой | реалистично, но фиксы ограничены байтовыми правками |
| **C. Декомпилировать/восстановить v20** | исходник «как v20» | 293 функции, ~107 КБ кода, ~4–5 тыс. строк; высокий риск, не рекомендуется |
| **D. Пересобрать из публичного v12** | ничего не теряем только в v12-функциях | **регрессия**: −293 функции, −Steam, −выбор отряда, −ceasefire, −hits/anim/craters и т.д. |

Что именно просить у автора, если он готов поделиться:

* дерево `basic_network` в состоянии, из которого собран `8108bd1e…` (network version 20):
  минимум `session.cpp`, `ui.cpp`, `state.cpp`, `statesync.cpp`, `shots.cpp`,
  `trench.cpp`, `xlate.cpp`, `protocol.h`, плюс новые файлы подсистем
  `steam`, `hit`, `anim`, `crater`, `clock`, `end`, `force`, `upnp`, `select`;
* либо более новый публичный коммит с этим исходником;
* желательно — авторский fake-Steam стенд и скрипты тестов (в репозитории их нет).

Публичный исходник v12 при этом **не бесполезен**: это читаемый предок общего ядра.
В нём есть те же `k_delay = 0.10`, `k_run_on = 0.25`, `MP_APPLY_DELAY = 12000 мс`,
таймаут 8 000 мс, обработчик HELLO, UPnP-поток, state-синхронизация. По нему можно
понимать смысл функций v20 и проектировать байтовые патчи (G1, G3, G4), но собрать
из него v20 нельзя.

## 8. Риски и открытые вопросы

* Steam-путь v20 **не проверен двумя реальными аккаунтами** — это ограничение upstream,
  а не нашего ребилда; наш модуль наследует его полностью.
* `k_version = 20`: совместимость только с v20-клиентами; v12-клиенты не подключатся.
* v20 собирался под build 3598; наш rebase — под 3598/1. На чужой сборке игры
  встроенные signature checks молча отключают часть функций (это защита, не падение).
* `mp_vitals.dll` привязан к точным RVA и байтам этого модуля; любой новый upstream
  билд требует нового профиля.
* Исходник v20 может существовать только локально у автора; публично его нет.
* Лицензия CC0-1.0 позволяет и патчить бинарник, и распространять производные.

## 9. Итог

1. v20 на GitHub есть — но **только бинарником** в `GTMPRelease1.zip`.
2. Публичный C++ — **v12**, на 293 функции и ~107 КБ кода меньше; он не является
   «v20 без Steam».
3. Наш мод **доказуемо** собран из v20 и содержит все его функции, включая Steam.
4. Для корневых фиксов нужен **исходник v20**; без него остаются точечные бинарные
   патчи, а пересборка из публичного дерева — регрессия.
