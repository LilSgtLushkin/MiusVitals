# Хуки и сборки игры: что сломало прошлый прогон и как это чинится

Дата: 2026-10-27. Основание: два архива логов от 26–27.10 и codelib'ы игры, присланные
пользователем (`x64.zip`: `adv_interf`, `adv_opgame`, `adv_game`, `base_main`, …).

## 1. Что показали логи

Модуль ставил шесть перехватов по фиксированным смещениям, взятым из v20. На установленной
сборке игры четыре из них не встали, и модуль честно сказал об этом:

| перехват | сообщение в логе | было |
|---|---|---|
| кнопка Start + две её части | `net: Start button not hooked (unknown game build)` | 2 прогона |
| сохранение операции (карта) | `map: unknown game build, the operation cannot be saved from here` | 7 |
| передача хода (карта) | `map: unknown game build, ending the turn is not coordinated` | 2 |
| часы боя | встал | — |

Следствия в том бою: гейта фаз не было (джойнер вышел в бой на 43 с раньше хоста), карту
операции отдать было нечем, меню джойнера отправило 1116 запросов кусков карты и не получило
ни одного ответа.

## 2. Где функции на этой сборке

Смещения — RVA от базы модуля. Найдены по подписям в присланных codelib'ах (`tools/pe_scan.py`
делает то же самое из Python):

| функция | модуль | v20 | эта сборка | подпись |
|---|---|---|---|---|
| Start (обработчик действия) | `adv_interf` | 0x3b3b0 | **0x3b320** | та же, 16 байт |
| Start (клавиша) | `adv_interf` | 0x3b4f0 | **0x3b460** | изменилась: `sub rsp,40h`, `rbx=r8` |
| Коробка «закончить развёртывание?» | `adv_interf` | 0x41700 | **0x41630** | та же, 15 байт |
| Часы боя | `base_main` | 0x4200 | 0x4200 | та же |
| Сохранение операции | `adv_opgame` | 0xd6660 | **0xd6080** | та же, 19 байт (сверяются 16) |
| Шаг, завершающий ход | `adv_opgame` | 0x76810 | **0x76510** | та же, 15 байт |
| Обработчик кнопки «следующий ход» | `adv_opgame` | 0x36b40 | **нет** | в этой сборке не найден ни разу |

Итог: четыре смещения просто сдвинулись (на 0x90, 0xd0, 0x5e0, 0x300), одна подпись изменилась
по форме, одна функция исчезла.

## 3. Как теперь ставится перехват

`src/hooks.cpp`, `hook_resolve(module, список кандидатов, что это)`:

1. по смещению, которое известно для этой сборки — без сканирования;
2. если байты не те — поиск подписи по исполняемой секции модуля;
3. перехват ставится только если подпись встретилась **ровно один раз**; два кандидата — это не
   повод гадать, функция остаётся невзятой, и в лог идёт причина.

Кандидатов можно перечислить несколько (по одному на встреченную сборку игры) — берётся первый
найденный. Так клавиша Start переживает изменение формы функции.

Заголовок лога теперь говорит, что нашлось, а что нет: `hooks: … is not where this build had it
(now +0x…), the scan found it and it is used` или `hooks: … the signature is not in <модуль> …`.

## 4. Карта операции без обработчика кнопки

Обработчика «следующий ход» в этой сборке нет, а шаг, который реально завершает ход, есть и
проверен. Поэтому конец хода координируется на шаге:

* игрок нажимает «следующий ход» и подтверждает его в родной коробке игры;
* перехват шага не даёт ходу завершиться, а запоминает «этот игрок закончил» и ждёт второго;
* когда закончили оба, хост выполняет шаг по-настоящему (флаг `g_turn_executing` отличает
  собственный вызов от нажатия игрока).

Это то же конечное состояние, что давал перехват кнопки в v20, но на проверенном хуке. Если в
будущей сборке кнопка снова найдётся по подписи, включатся оба хука и поведение станет как в v20.

## 5. Как пересчитать следующую сборку игры

```sh
python tools/pe_scan.py <codelib> --sig "48 89 5C 24 08 57 48 83 EC 40"   # где лежит подпись
```

1. взять новый `adv_interf.codelib` / `adv_opgame.codelib`;
2. найти подписи из таблицы §2 (и/или их префиксы) и записать новые RVA;
3. добавить в `install_detours()` / `install_map_detours()` ещё одного кандидата с этими RVA —
   старые остаются, потому что на старых сборках играют тоже;
4. прогнать CI: сборка и самотесты проверяют только код, правильность смещений подтверждает
   первая же строка лога в игре (`hooks: …`).
